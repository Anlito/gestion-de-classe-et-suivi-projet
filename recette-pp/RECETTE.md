# Recette PP, avant remplacement du Carnet

Cette copie utilise une base locale, un dossier Drive et un agenda de recette distincts. Le Carnet habituel reste inchangé. Aucun fichier privé n’est livré dans cette copie.

Le bouton **Démarrer la recette fictive** crée seulement deux élèves EXEMPLE, une note, une image jointe et un rendez-vous fictifs, lorsque la base de recette est vide. Il ne remplace jamais des données existantes. Sur le second appareil, recevoir d’abord les données par Drive plutôt que créer un autre jeu d’essai.

Dans Administration → Sauvegarde, utiliser le même identifiant client Google que dans le Carnet habituel et le même compte sur les deux appareils. L’origine du site est la même ; le dossier créé par cette copie se nomme **Carnet de classe · recette PP 2026-11**. Les identifiants des dossiers de production ne sont pas importés depuis une sauvegarde.

L’agenda de production n’est pas réutilisé. Après activation explicite, la copie utilise un nouvel agenda **Carnet de classe · recette PP 2026-11** et n’y envoie que les événements dont le titre commence par **[TEST PP]**. Aucun cours n’est envoyé et les réglages d’agenda éventuellement présents dans une sauvegarde sont ignorés par cette copie.

Les choix d’activation, formulaires familles et fichiers ajoutés sont réels dans leurs services respectifs si vous les utilisez. Pour la recette, conserver des noms et textes fictifs. Aucune invitation ni message n’est envoyé automatiquement par le jeu fictif.

Version de source et séparation des stockages : recette.json. Cette copie n’est pas une mise à jour du Carnet principal.
